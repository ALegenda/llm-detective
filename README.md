# Версия / llm-detective

Браузерная детективная игра со свободными вопросами и действиями, реальной генерацией самостоятельных дел, неизменной скрытой правдой и сохраняемым миром каждой попытки. Новая генерация разделяет причинную историю, схему доступа и диалоги; перед публикацией исполняет проверочное прохождение движком и независимо проверяет разгадку по доступным уликам. Подробности и границы гарантий — в [архитектуре](docs/ARCHITECTURE.md).

## Запуск

Python 3.11+. База и изображения хранятся в `data/`; не удаляйте её при обновлении.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# Заполните OPENAI_API_KEY в .env на сервере.
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Откройте [http://localhost:8080](http://localhost:8080). Создайте аккаунт, задайте тему и дождитесь подготовки. Изображения догружаются отдельно. Ни аккаунт, ни текст дела не отправляются каким-либо получателям вне подключённого AI-провайдера; почтовой рассылки нет.

Можно использовать существующий env-файл без копирования ключа:

```bash
ENV_FILE=/absolute/path/to/existing/.env .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

По умолчанию: `gpt-6-luna` для структурированных текстовых операций, `gpt-image-2.5-flare` для изображений и редактирования эмоций по референсу. Проверьте доступ и квоту своего проекта. Подмена настоящего API шаблонными ответами отсутствует.

## Как играть

- Общий осмотр отмечает ориентиры. Уточняйте, какой предмет или обстоятельство проверяете.
- Перед первым входом в попытку открывается вводная: предыстория, задача, известные обстоятельства и участники. Её можно перечитать через «Вводная дела». Новые дела получают развёрнутое досье; старые используют сохранённую вводную без изменения истории.
- Нажмите на персонажа, чтобы открыть отдельный чат: портрет, переписка и форма сообщения. У каждого собеседника своя история и свой черновик. Вернуться к осмотру можно через «К месту расследования».
- Сообщение в чате всегда является репликой. Физические действия выполняются в сцене. Если человек ушёл, история доступна, но отправка сообщений требует снова встретиться.
- Под именем собеседника выберите реальные предметы или записи для предъявления. Устное заявление может быть блефом.
- Карточка предмета бесплатно показывает внешний вид и доступные конкретные проверки с ценой во времени. Кнопки выполняют выбранное действие напрямую; свободное исследование остаётся доступным. Повтор готовой проверки открывает запись и не тратит минуты.
- Предметы можно брать, оставлять, применять; контейнеры — открывать доступным способом. Невозможное действие не становится успешным только из-за текста запроса.
- В блокноте записи сгруппированы по источникам, доступны поиск, фильтры и раскрытие полного текста. Показания сохраняют короткие дословные выдержки; приветствия и отказы не засоряют блокнот. Полные разговоры доступны в чатах, собственные гипотезы — в «Моих версиях».
- Ход расследования показывает последний результат со ссылками на новые записи; предыдущие действия свёрнуты в историю.
- Ответ персонажа проверяется на соответствие вопросу, фактам и речи от своего лица. Неудачная реплика переписывается; если проверка снова не пройдена, состояние не меняется и доступен повтор.
- Чтение и отсутствие в игре не расходуют минуты. Время идёт только после значимых действий.
- Завершение требует объяснения и подтверждения открытия разгадки. Повтор начинает чистую попытку той же истории, сохраняя старый разбор.

## Настройки

| Переменная | Назначение |
|---|---|
| `ENV_FILE` | Явно выбранный файл окружения вместо `.env` |
| `DATA_DIR` | Каталог БД и приватных изображений |
| `OPENAI_TEXT_MODEL`, `OPENAI_IMAGE_MODEL` | Модели диалогов/интерпретации (по умолчанию GPT-6 Luna) и изображений |
| `OPENAI_DIALOGUE_REASONING` | Ответы персонажей и проверка реплик: по умолчанию `low` |
| `OPENAI_TEXT_REASONING` | Быстрые игровые вызовы GPT-6: по умолчанию `none`; подготовка отдельно использует `medium` |
| `OPENAI_STORY_MODEL`, `OPENAI_STORY_REASONING` | Отдельная модель подготовки/проверок сюжета: по умолчанию `gpt-6-luna`, `medium` |
| `WORKERS` | 3–4 исполнителя: отдельные очереди команд, генерации и изображений; при 4 — два исполнителя генерации. Старое значение 2 повышается до 3 |
| `CASE_CALL_LIMIT` | Предел вызовов подготовки сюжета и изображений на дело, по умолчанию 140 |
| `ATTEMPT_CALL_LIMIT` | Отдельный бюджет действий на попытку, по умолчанию 200 вызовов |
| `DAILY_CALL_LIMIT` | Верхний предел вызовов на владельца за 24 часа, по умолчанию 500 |

Для явно разрешённых тестов значение `0` временно отключает соответствующий бюджет AI. После тестов восстановите исходные значения. Это не отменяет ограничения частоты и квоты провайдера.
| `APP_ENV` | `development` или `production` |
| `APP_ORIGIN` | Точный origin интерфейса; HTTPS обязателен в production |
| `ADMIN_EMAILS` | Администраторы через запятую; без значения доступ никому не выдаётся |
| `TELEGRAM_CLIENT_ID`, `TELEGRAM_CLIENT_SECRET` | Данные Web Login из BotFather; если оба значения заданы, на экране входа появляется Telegram |
| `TELEGRAM_ADMIN_IDS` | Числовые Telegram ID администраторов через запятую |

Административная страница `/\#/admin` показывает неудачные/зависшие операции, причины, повторы и фактическое потребление AI. Повышение бюджета — настройка оператора, не игровая покупка. Монетизации и имитации оплаты нет.

## Вход через Telegram

В [@BotFather](https://t.me/BotFather) создайте бота, откройте **Bot Settings → Login Widget** и добавьте разрешённые URL:

- `https://llm-detective.onrender.com`
- `https://llm-detective.onrender.com/api/auth/telegram/callback`

Скопируйте выданные Client ID и Client Secret в одноимённые переменные окружения. Алгоритм подписи должен оставаться стандартным `RS256`. Первый подтверждённый вход автоматически создаёт аккаунт; последующие входы находят его по постоянному Telegram ID. Телефон и разрешение на сообщения ботом не запрашиваются.

## Проверки

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check static/app.js  # необязательно: проверка синтаксиса frontend
ENV_FILE=/path/to/.env .venv/bin/python scripts/check_provider.py
# Явная проверка генерации и редактирования изображений: два платных вызова.
ENV_FILE=/path/to/.env .venv/bin/python scripts/check_provider.py --images
```

Каталог моделей может не содержать новую модель, даже если Images API уже работает: код выхода 3 означает непроверенную доступность изображения, а `--images` проверяет нужные endpoints напрямую.

После локального тестового входа скрипт `scripts/live_play.py` позволяет проходить дела через публичный API. `scripts/check_evaluation.py --attempt FINISHED_ATTEMPT_ID --expect proved` запускает платную проверку оценки уже завершённой попытки (до трёх вызовов; для неполной версии используйте `--expect partial`). Эти проверки включаются только явно, отдельно от CI.

Контролируемые фикстуры используются только тестами. Реальное качество контента и визуала проверяется отдельно; результаты и ограничения перечислены в [отчёте приёмки](docs/ACCEPTANCE.md).

## Резервное копирование

```bash
.venv/bin/python scripts/backup.py backup /safe/location/detective-backup
.venv/bin/python scripts/backup.py restore /safe/location/restored --source /safe/location/detective-backup
```

Восстановление требует новой, ещё не существующей директории. После проверки запустите сервер с `DATA_DIR=/safe/location/restored`. Храните резервные копии с теми же ограничениями доступа, что и оригинал.

## Контейнер

```bash
docker compose up --build
```

Compose использует `.env`, постоянный volume для данных и порт 8080 на loopback. Для внешнего рабочего запуска настройте HTTPS reverse proxy, `APP_ENV=production` и соответствующий `APP_ORIGIN`. Готового облачного размещения эта команда не создаёт.

## Развёртывание на Render

В корне репозитория есть Blueprint [`render.yaml`](render.yaml): Docker web-сервис, диск `/data` для SQLite и ассетов, health-check `/api/health`. Нужен платный инстанс (`starter` и выше) — на Free нет persistent disk, а без него база и картинки пропадут при редеплое.

1. Откройте [Blueprint Deploy](https://dashboard.render.com/blueprints/new?repo=https://github.com/ALegenda/llm-detective) (или **New → Blueprint** и выберите этот репозиторий).
2. Подтвердите сервис `llm-detective` и при запросе укажите `OPENAI_API_KEY`. Для Telegram-входа также укажите `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET` из BotFather.
3. После деплоя URL вида `https://….onrender.com` подставится сам (`RENDER_EXTERNAL_URL` → `APP_ORIGIN`). При своём домене задайте `APP_ORIGIN` вручную.
4. По желанию задайте `ADMIN_EMAILS` (через запятую) для `/#/admin`.

Для обновления существующего сервиса установите `OPENAI_IMAGE_MODEL=gpt-image-2.5-flare` в Render Environment (либо синхронизируйте Blueprint). Явно заданное старое значение окружения имеет приоритет над новым значением по умолчанию в коде. Ранее готовые изображения сохраняются; новые ассеты и эмоции используют выбранную модель. [Описание Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare).

Экономичный профиль изображений: `low`, WebP с `output_compression=80`, 832×832 для предметов/портретов и 1152×768 для фонов. Настройки вынесены в `.env.example`; PNG остаётся поддерживаемым для старых файлов и восстановления незавершённых задач. Сжатие экономит место, а выбор модели, качества и разрешения влияет на токены. Реальные байты и токены каждого нового результата записываются в `IMAGE_RENDERED`. [Хранение и проверка R2](docs/R2_STORAGE.md).

Локальный Docker/`uvicorn` не меняются: `PORT` по умолчанию 8080, на Render — из окружения.

[Архитектура](docs/ARCHITECTURE.md) · [Исходная спецификация](docs/PRODUCT_SPEC.md) · [Приёмка и границы реализации](docs/ACCEPTANCE.md)

Итоговый отчёт и проверка снятых баллов используют `OPENAI_EVALUATION_REASONING=medium` независимо от `OPENAI_DIALOGUE_REASONING=low`. Перед публикацией оценки каждое снижение по критерию и каждая ошибочная реплика проходят отдельную проверку по полному тексту отчёта, выбранным уликам и выполненным действиям. Необоснованное снижение запускает пересмотр; это дополнительный AI-вызов только для оценок со снятыми баллами. Старые итоги сохраняются.
