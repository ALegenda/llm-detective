# Архитектура «Версии»

Один Python/FastAPI сервис, статический браузерный клиент и SQLite WAL на локальном диске. PostgreSQL, Redis, Node и сборка frontend для запуска не требуются. Несколько фоновых потоков исполняют сохранённые задачи; число потоков ограничено. Для масштабирования на несколько машин потребуется внешнее хранилище/очередь — SQLite на сетевой файловой системе не поддерживается.

## Авторитетные данные

`cases.blueprint` — проверенная неизменная исходная история: объективная правда, граф мест, предметы, физические проверки, личные знания NPC и правила реакций. Изначальная генерация может исправляться только до статуса ready. `attempts.initial_state` и `attempts.state` отделяют чистое начало от прохождения. Повтор не вызывает генератор.

`world.py` — чистый проверяющий редуктор. Он единолично изменяет местоположение, владение предметами, состояние контейнеров, игровые минуты, знание NPC, наблюдения и последствия. AI возвращает структурированное предложение; никакие свободные JSON-патчи или Python/JavaScript от модели не исполняются.

Кнопки предметов передают точный тип действия, object id и check id; сервер сверяет видимость и предпосылки, а редуктор исполняет действие без языкового интерпретатора. Публичная карточка содержит только доступные intent/стоимость/статус проверок, без результатов и скрытых предпосылок.

Интерпретатор видит публичное окружение и описания доступных проверок без их результатов. Семантическое сопоставление намерений делает LLM. Если проверки нет, движок не придумывает решающую улику. Собеседник видит собственные знания и допустимые показания, память, реально предъявленные сведения и историю только своего разговора. Независимая проверка ответа отсеивает неподтверждённые существенные утверждения; проверяются также соответствие последнему вопросу и речь от первого лица. Неудачный ответ проходит один цикл переписывания с замечаниями; при повторной неудаче команда остаётся восстанавливаемой без изменений мира. Выдержки для блокнота выбираются проверяющим из точных фрагментов уже созданной реплики через динамическую схему, а не набираются повторно. Допускается релевантная часть многосоставного показания. Авторские claims никогда не подставляются в диалог как резервный ответ. Это ограничение вероятностной модели, а не математическая гарантия отсутствия галлюцинаций.

Наблюдения, физические предметы и утверждения персонажей различаются и имеют источник, место и игровое время. Итоговый оценщик получает скрытую правду только после подтверждённого завершения; промежуточной оценки виновности нет. Финальная схема разрешает цитаты только из предложений игрока и ссылки только на выбранные им доказательства. Критерии фиксированы самим делом и общими требованиями идентификации и причинного объяснения; итоговый статус вычисляется из их оценок, а не из свободного заключения модели.

## Согласованность и восстановление

Создание дела и постановка его задачи происходят в одной короткой SQLite-транзакции. Запросы создания, действий и повтора имеют ключ идемпотентности. Повтор ключа с другим телом отклоняется. Для одной попытки одновременно допускается одна активная команда; версия дополнительно проверяется перед фиксацией результата. Текстовые вызовы выполняются без длительной транзакции БД.

Задачи захватываются с уникальным fencing token и сроком владения. Heartbeat продлевает срок; новый исполнитель после истечения заменяет токен. Старый исполнитель не может сохранить результат. Готовые стадии сохраняются в checkpoint. Структурированные ответы также кэшируются в БД в пределах конкретной задачи и точного контекста/модели/схемы. Сбой после внешнего успеха, но до локального сохранения всё ещё может вызвать дополнительный платный вызов; такой исход не выдаётся за бесплатный повтор.

Таймауты и 429/5xx восстанавливаются ограниченно с задержкой и jitter. Ошибки доступа/квоты — постоянные. Ошибки содержания имеют отдельный ограниченный цикл исправления с исходным черновиком и замечаниями. После предела операция видна как неудачная. Администратор или владелец могут повторить только этот этап, с записью аудита. Пользовательские ручные повторы также ограничены.

Состояние, события и результат команды сохраняются атомарно. Представление использует уже сохранённый результат. Повтор страницы не тратит минуты. Фоновые задачи изображений и часы реального времени никогда не продвигают NPC.

## Генерация v2: история → компилятор → проверяемая игра

Новые дела больше не создаются одним вызовом, который одновременно изобретает сюжет и программирует мир. Сохранённые дела неизменны; незавершённые задания v1 сохраняют прежний путь восстановления.

1. **Причинная история.** Автор фиксирует прошлое, мотивы, личные знания, невиновные секреты, материальные источники и проверяемые выводы. Для каждого обязательного вывода нужны как минимум два разных материальных источника. Подсказки и разговоры не являются единственным путём решения. Качество независимости источников дополнительно проверяется смысловым аудитом; разные ID сами по себе его не доказывают.
2. **Схема доступа.** Отдельный вызов выбирает поддерживаемые механики: открытый источник, источник в контейнере, запертый контейнер, инструмент, сравнение наблюдений. Динамическая схема разрешает только существующие комнаты и ссылки на более ранние наблюдения, исключая циклы предпосылок. Код назначает ID, создаёт ключи и инструменты вне контейнеров, связывает помещения и компилирует итоговый `Blueprint`. Слова модели не становятся физическим эффектом.
3. **Исполнимый сертификат.** Автоматический игрок обходит мир в двух порядках и выполняет обычные переходы, взятия, открытия и проверки через `world.reduce`. Требуется получить все обязательные наблюдения, два источника для каждого критерия и физически взять предметы, обозначенные как пропавшие. Сертификат — конкретная последовательность исполненных действий, а не ответ модели «проходимо».
4. **Диалоги и вводная.** Автор пишет их для уже собранного мира. Все ссылки на предъявляемые улики ограничены существующими ID. Предметы через разговор не выдаются. Скрытые знания остаются личными, реплики — от первого лица.
5. **Независимое решение.** Другой вызов получает доступные игроку материальные наблюдения и публичную вводную, без признаний персонажей, скрытой правды, личных справок, авторских значений улик и намеченных выводов. Он объясняет кто/как/почему и отмечает неоднозначности.
6. **Смысловой аудит.** Сопоставляются причинная история, фактическое состояние, реплики и независимое решение. Только конкретные противоречия и недоказанные выводы требуют исправлений. Возражения аудитора проходят отдельное обоснование: нужны несовместимые факты, а вложенные контейнеры, допустимая ранняя находка и предпочтения формулировки не считаются противоречием. Замечание адресуется конкретному этапу/источнику. Исправление вводной не перегенерирует мир и прошлое. После изменения схемы доступа исполнимый сертификат строится заново.

Checkpoint хранит каждый этап и его редакцию. Число содержательных исправлений ограничено: максимум два автоматических продолжения для одного этапа и четыре по всему конвейеру. Сетевая ошибка не обнуляет уже завершённые этапы. Публичная страница показывает реальные названия этапов, но не раскрывает сертификат, черновики или разгадку.

**Границы гарантий.** Механическая доступность подтверждается настоящим движком в двух порядках обхода. Это не доказательство всех возможных последовательностей и не математическая гарантия литературной логики. Семантика, интерес и корректность живого диалога дополнительно зависят от моделей и проверяются пользовательским прохождением. Новая версия намеренно использует ограниченный набор безопасных механик: связный мир с центральной локацией, обратимые действия, доступные инструменты, без автоматически сгенерированных уходов важных свидетелей. Сложность строится на сопоставлении фактов; старый движок и сохранённые миры продолжают поддерживать прежние реакции.

## Иллюстрации

Локация — фон архитектуры, отдельно от интерактивных объектов и присутствующих персонажей в сцене. Взятие/перемещение/открытие меняет интерактивный слой. Это композиция интерфейса, не пространственный 3D-движок.

У персонажа сначала создаётся и проверяется базовый образ. Эмоции делаются через Images Edits с базовой картинкой в качестве входа; проверяются узнаваемость, одежда и кадрирование. Сначала загружаются стартовая локация и нужные персонажи, затем остальные изображения. Недоступная эмоция заменяется базовой. Предметы генерируются по открытому внешнему описанию, без скрытых надписей и содержимого.

Файлы проверяются Pillow, записываются через временный файл и переименование, затем проходят визуальную проверку моделью. В БД хранятся версия стиля, модель, происхождение и базовый образ. Доступ выдаётся только через проверяющий владельца маршрут, не через публичную папку. Набор иллюстраций не объявляется профессионально проверенным только потому, что API вернул файл.

## Эксплуатация

Нет демонстрационного режима или автоматической подмены API. Отсутствие ключа — явная ошибка запуска. Ключ хранится только в окружении сервера/игнорируемом env-файле. Аккаунты: scrypt, случайные серверные сессии, HttpOnly/SameSite cookie; production требует HTTPS origin и Secure cookie. Мутации проверяют Origin и специальный заголовок. Сырые запросы и диалоги не пишутся в технические логи.

`operations` связывает вызовы с пользователем, делом и задачей, хранит модели, статусы, request id, токены и длительность. Ограничены число вызовов на дело/сутки, генераций в час, параллелизм и размер ответа. Денежный счёт остаётся у провайдера: счётчики токенов и вызовов не обещают точную цену.

Миграции выполняются по `PRAGMA user_version`, более новая БД отклоняется. `scripts/backup.py` использует SQLite backup API и копирует только связанные ассеты, создаёт SHA-256 manifest и проверяет целостность при восстановлении в новую директорию. Возобновление сохранения не требует повторной генерации уже произошедших событий.
